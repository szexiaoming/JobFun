# Iteration 0.42 — 岗位差距解释助手

状态：**本地功能已实现；真实供应商调用与用户评估待完成**。

## 用户流程

用户打开已有匹配的申请详情，在逐项岗位要求中选择一条并提交解释。页面展示任务进度，完成后按“要求、证据、待核实段落、下一步行动”显示结果。证据和候选段落均可定位到该申请绑定的简历快照。解释任务不会修改简历、匹配分数或申请状态。

## 数据与安全边界

- 客户端只提交 `application_id` 和 `requirement_key`；服务端从认证上下文取得用户 ID，并核对申请、匹配、岗位和简历的关联。历史申请始终使用保存时绑定的版本。
- `GET /api/v1/applications/{application_id}/requirements` 从岗位结构化内容列出要求，并读取该匹配已有的逐条证据。缺少证据行时标记为“尚未逐条评估”。
- 新解析的岗位和新匹配会准备逐条要求；历史匹配在用户首次请求解释时按需准备要求并尝试 Evidence Matcher。若模型不可用，仍返回不宣称掌握技能的基础解释。
- 已保存的证据在展示前重新核对 `source_id`、简历原文、章节、经历和 bullet 位置。无法核对的正向证据降为“待确认”；用户已拒绝的证据不作为证明。
- 相似度检索只产生候选段落，不能改变匹配状态。候选段落必须来自当前申请绑定的简历；提示用户人工核实。
- 成功结果保存在用户所属的操作任务数据中，现有账户导出与删除流程覆盖这类数据。没有新增跨用户共享的持久向量库。

## LangChain 与检索

`src/ai/langchain_gap.py` 使用 LangChain `create_agent` 和三个只读工具：读取选中要求、读取已校验的证据、检索当前简历候选段落。Agent 只能返回受约束的行动类型与最多三个候选 `source_id`；面向用户的事实性文字由服务端模板生成，避免模型自由编写履历结论。调用上限为八步。

候选检索在本次请求内用 LangChain Chroma 和 Hugging Face 嵌入构建临时索引，元数据包含用户、简历版本和来源 ID；查询同时按用户和简历版本过滤，结束后删除集合。向量依赖缺失或查询失败时退回词项检索；语言模型或 LangChain 不可用时使用确定性基础解释。安装可选依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-langchain.txt
```

语言模型沿用服务端 `AI_PROVIDER` 与相应 API Key；Codex 是开发工具，不作为运行时供应商。首次向量检索可能需要下载嵌入模型；没有模型文件或网络时会退回词项检索。当前未对真实供应商请求、下载耗时或实际费用作验收。

## 接口与验证

- `POST /api/v1/applications/{application_id}/gap-explanations`：要求 `Idempotency-Key`，提交 `requirement_key`，返回异步操作。
- `GET /api/v1/gap-explanations/{operation_id}`：仅向所属用户返回已完成的结果；任务状态由既有 `/operations/{id}` 查询。
- Next.js 经同源 BFF 和 HttpOnly Cookie 调用接口，不把 Bearer Token 暴露给浏览器脚本。
- 测试覆盖幂等重放、跨用户拒绝、历史版本引用、篡改证据降级、无模型基础解释、真实 LangChain 工具流程和临时向量检索。

后续评估应使用人工标注样本检查状态与引用准确率，并记录真实模型工具成功率、延迟和成本。没有真实用户数据前，不宣称使用率或求职结果改善。
