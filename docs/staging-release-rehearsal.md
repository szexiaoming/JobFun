# JobFun 私有预发布验收与恢复演练

适用版本：Web `0.41.0`、FastAPI `0.31.0`。本方案只用于隔离预发布环境，不创建云资源、不连接生产数据，也不代表已经公开部署。

## 1. 验收目标

本轮验证配置、依赖、进程和恢复流程能否组成可发布闭环：

1. PostgreSQL 与 S3 兼容对象存储只承载合成数据；
2. 发布配置通过不泄露取值的自动门禁；
3. API、Worker 与 Web 分进程启动；
4. 三个健康契约全部通过；
5. Worker 异常、队列积压与恢复可被观察；
6. 数据库和对象存储备份能够在新的隔离目标中恢复；
7. 验收记录不包含简历、面试回答、Token、密钥或内部对象键。

## 2. 开始前的硬性条件

- 环境名称明确为 `staging`，域名、数据库、Bucket 和告警通道均不得与生产共用；
- 数据只使用测试工厂或人工构造的虚拟履历、岗位和音频；
- Secret 通过环境注入，不写入命令历史、截图、日志或仓库；
- HTTPS 终止、`Secure` Cookie 和同源 BFF 已就位后，才验收登录与写流程；
- 至少两名操作者确认恢复目标是空的隔离数据库和空的隔离 Bucket；
- 任何目标名称、账户或网络边界不清楚时立即停止。

本机依赖模板位于 [`../infra/staging/README.md`](../infra/staging/README.md)。模板不会自动启动。

## 3. 配置门禁

在准备好的进程环境中运行：

```powershell
.\.venv\Scripts\python.exe -m src.ops.preflight --env-file infra/staging/application.env --strict
```

门禁只输出检查名称、级别和修复提示，不输出 DSN、Bucket 名、API Key 或 Webhook Token。默认模式允许“语音未配置”和“告警未配置”警告；正式预发布验收使用 `--strict`，让警告也阻止继续。

机器可读结果：

```powershell
.\.venv\Scripts\python.exe -m src.ops.preflight --env-file infra/staging/application.env --strict --json
```

退出码 `0` 才能进入启动阶段，退出码 `1` 表示环境未满足门禁。不要通过修改检查代码来绕过失败项。

## 4. 启动与只读健康验收

按顺序启动 PostgreSQL/S3、FastAPI、Worker、Next.js。Worker 必须使用唯一名称持续运行，Web 不得获得数据库或 AI 密钥。

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api.app:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m src.api.run_jobs --watch --limit 5 --poll-interval 2
```

显式指定 API 地址执行只读验收：

```powershell
.\.venv\Scripts\python.exe -m src.ops.verify_health --base-url https://staging-api.example.test --json
```

脚本只发送四个无凭据 `GET` 请求：`/health/live`、`/health/ready`、`/health/worker`、`/health/maintenance`。任一非 200、无效 JSON 或状态不匹配都会返回退出码 `1`。

## 5. 合成业务冒烟

只使用专用测试账户完成一次最小闭环：

1. 导入虚拟简历和虚拟岗位；
2. 等待两个解析任务完成；
3. 执行一次匹配并确认报告有五维证据；
4. 创建申请并沿合法状态机推进一步；
5. 提交文字面试回答并读取四维评价；
6. 若语音已配置，上传无个人信息的短音频，确认转写后原音频默认删除；
7. 主动保留另一条合成音频，确认音频管理页可见、批量删除可用，并用缩短的测试保留期验证自动清理；
8. 确认 `/health/maintenance` 记录本轮扫描/删除数量；模拟一次失败时只进入 warning，连续达到测试阈值后进入 alerting；
9. 导出该测试账户，再执行受控删除，确认对象清理完成。

不得为了通过冒烟而直接修改数据库状态或任务结果。

## 6. Worker 与队列故障演练

### Worker 崩溃恢复

1. 在合成任务运行期间正常终止一个 Worker 进程；
2. 确认心跳超过阈值后 `/health/worker` 返回 503，监控测试通道收到告警；
3. 核实没有第二个 Worker 仍在执行同一任务后，按既定重试策略处理停滞任务；
4. 重启相同身份或新的唯一身份 Worker；
5. 确认健康恢复、任务没有重复业务结果、告警关闭。

### 队列积压

1. 暂停领取任务，不停止 API；
2. 通过正常 API 提交少量合成任务；
3. 等待最老任务超过测试阈值，确认 `queue=backlogged`；
4. 恢复 Worker，观察队列年龄和数量回落；
5. 核实日志与告警中没有用户内容或密钥。

禁止批量直接修改所有 `running` 任务为 `queued`。

## 7. 备份与恢复演练

### 备份

- PostgreSQL 使用组织批准的 `pg_dump` 工具生成自定义格式、加密存放的快照；
- S3 兼容存储使用版本化复制或批准的同步工具复制到独立私有备份位置；
- 记录数据库快照时间、对象快照时间、应用版本和迁移版本，不记录密钥；
- 对备份文件计算校验和，并把校验和与备份分开保存。

### 恢复前确认

恢复属于破坏性操作，只能由操作者手动执行。执行前必须同时满足：

- 目标名称带有明确的 `restore-test` 标记；
- 目标数据库为空且没有应用连接；
- 目标 Bucket 为空、私有且不属于生产账户；
- 原预发布环境保持只读或已停止写入；
- 已记录回退方式和演练负责人。

### 恢复后验证

1. 使用批准工具把数据库快照恢复到全新的 `restore-test` 数据库；
2. 把对象快照恢复到全新的私有 `restore-test` Bucket；
3. 将应用临时指向恢复目标，先运行配置门禁；
4. 只读运行健康检查和记录数量/关联完整性检查；
5. 抽查合成文件可读、已删除对象未复活、账户隔离仍有效；
6. 运行最小业务冒烟，不再写回原环境；
7. 记录 RPO、RTO、缺失对象和人工步骤；
8. 演练结束后按审批流程销毁恢复目标，而不是由脚本自动清理。

## 8. 发布判定

只有以下项目全部有证据时才可建议进入实际部署决策：

- 配置门禁严格模式通过；
- `npm run check` 和完整 Python 测试通过；
- PostgreSQL 契约测试在隔离库通过；
- 三个健康检查稳定通过；
- 合成业务冒烟通过且没有越权或敏感信息泄露；
- Worker 崩溃和队列积压演练均能告警并恢复；
- 数据库与对象存储恢复演练达到约定 RPO/RTO；
- HTTPS、域名、Secret 管理、轮换、备份保留和责任人已经确定。

本文件完成不等于这些外部条件已经完成。真实基础设施和发布目标仍需用户明确指定后再执行。
