# JobFun — AI 求职 Agent 项目综述

## 1. 项目概述

**项目名称**：JobFun（开发代号：GitHub-Career-Agent）

**一句话简介**：面向技术求职者的 AI Agent 平台，结合 RAG 知识库、GitHub 项目分析和 LLM 推理能力，提供从简历优化到面试准备的端到端求职辅助。

**核心价值主张**：

```
简历 + 岗位JD + GitHub项目 + 求职知识库
        ↓
  RAG 检索增强 + 工具链计算
        ↓
  Agent 多维度分析与报告生成
        ↓
  简历优化 / 项目包装 / 面试计划 / 薪资分析
```

## 2. 项目背景

### 2.1 痛点分析

| 痛点 | 描述 |
|------|------|
| **简历与JD脱节** | 求职者不知道如何将自己的经历与目标岗位对齐 |
| **GitHub项目浪费** | 有优质开源项目但不会在简历中包装和表达 |
| **面试准备无方向** | 不知道面试官会针对自己的项目问什么 |
| **薪资信息不透明** | 不了解薪资结构（基本工资/公积金/年终奖等）对实际收入的影响 |
| **AI工具同质化** | 市面上多数"AI简历工具"只是套壳ChatGPT，缺乏专业知识库支撑 |

### 2.2 差异化定位

- **内置求职知识库（RAG）**：不是简单地调 LLM，而是基于结构化的求职知识库进行检索增强
- **GitHub 项目深度分析**：能分析 README、技术栈、项目结构，生成简历 bullet
- **确定性工具链**：薪资计算、关键词匹配、项目评分等由 Python 代码计算，不依赖 LLM
- **诚实边界**：坚决拒绝伪造经历，只做真实经历的优化和包装

## 3. 目标用户

### 3.1 核心用户

- 计算机/软件工程/人工智能相关专业学生
- 数据科学/AI/机器学习方向求职者
- 软件开发/测试开发/QA Engineering 求职者
- AI 应用工程/Agent 开发/RAG 开发方向求职者
- 机器人/自动化/控制/嵌入式方向求职者
- 有 GitHub 项目但不知道如何表达的开发者

### 3.2 次级用户

- 数据分析方向求职者（偏技术）
- 产品经理（偏技术产品）
- UI/UX 设计师（有前端作品集）
- HR/猎头（反向使用，分析候选人）
- 转行/转 AI 应用方向的求职者

### 3.3 非目标用户

- 完全没有技术项目的人
- 不使用 GitHub 也没有项目材料的人
- 只需要通用模板的求职者
- 试图伪造经历的人（系统会拒绝）

## 4. 项目目标

### 4.1 业务目标

1. 帮助技术求职者完成从"原始素材"到"高质量求职材料"的转化
2. 将 GitHub 项目转化为简历中的核心竞争力
3. 为每位求职者生成个性化的面试准备计划
4. 提供透明的薪资计算和 offer 对比分析

### 4.2 技术目标

1. 构建可独立运行的 RAG 知识库模块
2. 实现 LLM 推理 + 确定性工具计算的混合架构
3. 建立 AgentEval 自动化测评体系（40+ case，10 个类别）
4. 通过 FastAPI 提供标准化 API 服务
5. 全流程支持 CLI 和 API 两种使用方式

## 5. 项目范围

### 5.1 MVP 范围（Phase 1-2）

- RAG 知识库（TF-IDF 检索 + Markdown 知识文件）
- LLM Agent 核心流程（JD分析 → 简历分析 → GitHub分析 → 匹配 → 建议 → 报告）
- 6 个确定性工具（JD解析、简历解析、GitHub解析、匹配评分、薪资计算、关键词匹配）
- Markdown + JSON 报告输出
- CLI 运行方式

### 5.2 完整范围（Phase 3-5）

- AgentEval 自动化测评系统（40 cases, CSV + HTML 报告）
- FastAPI RESTful API（5 个端点）
- 向量检索升级（FAISS/ChromaDB）
- GitHub 展示材料（README, 架构图, Demo 脚本）

### 5.3 暂不包含

- 多用户系统 / 用户认证
- 数据库持久化
- 前端 UI
- 在线部署（SaaS）
- 实时爬取 GitHub 仓库

## 6. 关键成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| RAG 检索命中率 | > 80% | AgentEval rag_retrieval case 通过率 |
| JD 解析准确率 | > 85% | AgentEval jd_extraction case 通过率 |
| 安全拒绝率 | 100% | AgentEval safety_honesty case 通过率 |
| 报告完整性 | 12 个章节全覆盖 | 报告结构检查 |
| AgentEval 总通过率 | > 70% | 40 个 case 综合评分 |
| API 响应时间 | < 30s（非流式） | 性能测试 |

## 7. 项目约束

1. **语言**：Python 3.10+
2. **LLM 提供商**：需支持 Anthropic API（Claude）以及可配置的其他提供商
3. **部署形式**：CLI 工具 + API 服务，暂不需要 Web UI
4. **数据隐私**：所有数据本地处理，不上传用户简历到第三方
5. **许可**：MIT License
6. **MVP 免外部 Embedding API**：第一阶段使用本地 TF-IDF，降低使用门槛
