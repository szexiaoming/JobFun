# JobFun 软件需求规格说明书 (SRS)

## 1. 引言

### 1.1 文档目的

本文档定义 JobFun（GitHub-Career-Agent）项目的功能性需求和非功能性需求，作为后续架构设计、开发实现和测试验收的基准。

### 1.2 适用范围

适用于 JobFun 项目 MVP 至完整版本的全部开发阶段。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| JD | Job Description，岗位描述 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| AgentEval | Agent Evaluation，本项目自建的 AI Agent 自动化测评框架 |
| KB | Knowledge Base，知识库 |
| Chunk | 文档片段，RAG 检索的最小单元 |

---

## 2. 功能需求

### 2.1 RAG 知识库模块

#### FR-RAG-001：文档加载

- **优先级**：P0（MVP 必选）
- **描述**：系统应能读取 `data/knowledge_base/` 目录下的所有 Markdown 文件
- **输入**：知识库目录路径
- **输出**：文档列表，每个文档包含内容和元数据
- **元数据字段**：`source_file`, `section_title`, `doc_type`
- **验收标准**：
  - [ ] 能加载不少于 10 个 MD 文件
  - [ ] 每个文档包含完整的 metadata
  - [ ] 解析 Markdown 标题层级，正确提取 section_title

#### FR-RAG-002：文档分块

- **优先级**：P0（MVP 必选）
- **描述**：按 Markdown 标题结构智能分割文档为 chunks
- **分块策略**：
  - 优先按 `##` 二级标题分割
  - 每个 chunk 控制在 300-800 字符
  - 过短 chunk（<100 字符）与相邻 chunk 合并
  - 保留原始 metadata
- **验收标准**：
  - [ ] 分块后无信息丢失
  - [ ] chunk 大小符合范围（容差 ±20%）
  - [ ] metadata 正确传递到每个 chunk

#### FR-RAG-003：TF-IDF 检索

- **优先级**：P0（MVP 必选）
- **描述**：基于 TF-IDF 的关键词检索，不依赖外部 API
- **输入**：query（查询字符串）、top_k（返回数量，默认5）、filters（可选过滤条件）
- **输出**：`List[RetrievedChunk]`，每个包含 content、score、source_file、section_title
- **过滤支持**：按 `doc_type` 过滤
- **验收标准**：
  - [ ] 检索延时 < 500ms（本地，1000 chunks 以内）
  - [ ] 相关 chunks 能命中查询关键词
  - [ ] 过滤功能正常工作

#### FR-RAG-004：知识库统一封装

- **优先级**：P0（MVP 必选）
- **描述**：KnowledgeBase 类封装加载、索引构建、检索的完整流程
- **接口**：
  - `build_index()` — 构建检索索引
  - `retrieve(query, top_k, filters)` — 检索接口
- **验收标准**：
  - [ ] 单次初始化后可直接检索
  - [ ] 索引可重建（rebuild）

#### FR-RAG-005：来源引用

- **优先级**：P0（MVP 必选）
- **描述**：Agent 输出必须包含 `rag_sources` 字段，注明使用的知识来源
- **格式**：
  ```json
  {
    "rag_sources": [
      {
        "source_file": "github_project_rules.md",
        "section_title": "README 编写",
        "reason": "用于生成 GitHub 项目优化建议"
      }
    ]
  }
  ```
- **验收标准**：
  - [ ] 每个 RAG 知识驱动的建议都有来源引用
  - [ ] Markdown 报告末尾包含"参考知识来源"章节

### 2.2 Agent 核心模块

#### FR-AGENT-001：CareerAgent 主流程

- **优先级**：P0（MVP 必选）
- **描述**：编排从输入到输出的完整分析流程
- **输入**：
  ```json
  {
    "resume_text": "简历文本",
    "job_description": "岗位 JD 文本",
    "github_projects": [
      {
        "project_name": "项目名",
        "readme_text": "README 内容",
        "repo_structure": "项目结构（可选）",
        "tech_stack": ["技术栈列表"]
      }
    ],
    "target_role": "目标岗位",
    "target_city": "目标城市（可选）",
    "salary_info": {}
  }
  ```
- **输出**：13 个字段的完整分析结果（见下文 FR-AGENT-002）
- **处理步骤**：
  1. 加载输入
  2. 解析 JD
  3. 解析简历
  4. 解析 GitHub 项目材料
  5. RAG 知识库检索
  6. 简历-JD 匹配评分
  7. GitHub 项目组合评分
  8. 薪资计算（如有薪资信息）
  9. 生成简历优化建议
  10. 生成 GitHub 项目包装建议
  11. 生成面试准备计划
  12. 安全/诚信检查
  13. 输出 JSON + Markdown 报告
- **验收标准**：
  - [ ] 端到端流程无中断
  - [ ] 每个步骤的输出结构符合 schema 定义
  - [ ] 步骤 5-11 的内容引用了 RAG 检索结果

#### FR-AGENT-002：输出结构

- **优先级**：P0（MVP 必选）
- **描述**：Agent 输出必须包含以下全部字段：
  - `job_analysis` — 岗位分析结果
  - `resume_analysis` — 简历分析结果
  - `github_project_analysis` — GitHub 项目分析列表
  - `rag_context` — 检索到的知识上下文
  - `match_result` — 匹配评分结果
  - `github_portfolio_score` — 项目组合评分
  - `salary_analysis` — 薪资分析
  - `resume_advice` — 简历优化建议列表
  - `github_project_advice` — 项目包装建议列表
  - `interview_plan` — 面试准备计划
  - `risk_and_gap_analysis` — 风险与差距分析
  - `final_report_markdown` — 完整 Markdown 报告
  - `rag_sources` — 知识来源引用列表
- **验收标准**：
  - [ ] 13 个字段全部存在且类型正确
  - [ ] 不能有空字符串替代有效内容（除非输入确实缺少信息）

### 2.3 工具模块

#### FR-TOOL-001：JD 解析器

- **优先级**：P0（MVP 必选）
- **描述**：解析岗位 JD，提取结构化信息
- **输出结构**：
  - `job_title`, `job_family`（6 个类别之一）, `required_skills`, `preferred_skills`
  - `responsibilities`, `experience_requirements`, `project_expectations`
  - `difficulty`（low/medium/high）, `keywords`
- **鲁棒性要求**：
  - LLM JSON 解析失败时降级为正则提取
  - 不能编造 JD 中不存在的需求
- **验收标准**：
  - [ ] job_family 分类准确率 > 85%
  - [ ] 关键词提取覆盖 JD 中 80% 以上的硬技能要求
  - [ ] 各种格式的 JD 文本（纯文本/Markdown/HTML片段）都能解析

#### FR-TOOL-002：简历解析器

- **优先级**：P0（MVP 必选）
- **描述**：解析简历文本，提取结构化信息
- **输出结构**：
  - `education`, `work_experience`, `projects`, `skills`
  - `certificates`, `languages`, `strengths`, `risks`
  - `missing_information`
- **关键约束**：
  - 只提取简历中实际存在的信息
  - 缺失信息标注为 `missing`，不编造
- **验收标准**：
  - [ ] 不编造任何信息（100% 基于输入）
  - [ ] missing_information 字段准确标注所有缺失项

#### FR-TOOL-003：GitHub 项目解析器

- **优先级**：P0（MVP 必选）
- **描述**：解析 GitHub 项目材料，提取项目特征
- **输出结构**：
  - `project_type`（项目类型分类）
  - `tech_stack_detected`（检测到的技术栈）
  - `strengths`（优点列表）
  - `weaknesses`（不足列表）
  - `resume_bullets`（可用的简历描述 bullet）
  - `readme_advice`（README 改进建议）
  - `score`（综合评分 0-100）
- **评分维度**（7 个维度，总分 100）：
  - README 完整度：20%
  - 技术栈清晰度：15%
  - 工程结构：15%
  - 测试/评价：15%
  - 部署/运维：15%
  - 业务价值：10%
  - 面试可讲性：10%
- **验收标准**：
  - [ ] 7 个评分维度全部评估
  - [ ] 不编造项目中没有的功能
  - [ ] resume_bullets 可直接用于简历

#### FR-TOOL-004：匹配评分器

- **优先级**：P1（Phase 2）
- **描述**：量化简历与 JD 的匹配程度
- **评分维度**：
  - 技能匹配：30%
  - 项目匹配：25%
  - 工作/实习经验匹配：20%
  - GitHub 项目支撑度：15%
  - 学历/证书匹配：5%
  - 目标岗位一致性：5%
- **输出**：
  - `overall_score`（0-100）
  - 各维度得分
  - `matched_points`, `missing_points`
  - `risks`（风险列表）
  - `recommendation`（strong_match / possible_match / weak_match）
- **验收标准**：
  - [ ] 评分计算由 Python 代码完成，不用 LLM 直接打分
  - [ ] 每个维度的评分有可追溯的依据

#### FR-TOOL-005：薪资计算器

- **优先级**：P1（Phase 2）
- **描述**：根据中国薪资结构精确计算年收入
- **输入参数**：
  - `monthly_salary`：月薪
  - `salary_months`：年薪月数（13/14/15 薪）
  - `probation_salary`：试用期薪资
  - `probation_months`：试用期月数
  - `fund_base`：公积金基数
  - `fund_rate`：公积金比例
- **输出**：
  - `normal_annual_package`：正常年包
  - `first_year_package`：首年实际收入（考虑试用期）
  - `monthly_fund_employee`：个人月公积金
  - `monthly_fund_company`：公司月公积金
  - `notes`：计算说明
- **关键约束**：100% Python 确定性计算，不用 LLM
- **验收标准**：
  - [ ] 计算结果与手动计算一致（误差 < 1 元）
  - [ ] AgentEval salary_calculation case 全部通过

#### FR-TOOL-006：关键词匹配器

- **优先级**：P1（Phase 2）
- **描述**：提取和匹配 JD 与简历的关键词
- **功能**：
  - 从 JD 提取关键技能词
  - 在简历中检测这些关键词的出现
  - 生成缺失关键词列表
  - 建议在简历中添加的关键词（基于真实技能）

#### FR-TOOL-007：报告生成器

- **优先级**：P0（MVP 必选）
- **描述**：生成结构化 Markdown 报告
- **报告章节**（12 章）：
  1. 岗位分析
  2. 候选人简历分析
  3. GitHub 项目分析
  4. RAG 知识库参考
  5. 岗位匹配度评估
  6. 简历优化建议
  7. GitHub 项目包装建议
  8. 面试准备计划
  9. 薪资与 Offer 分析
  10. 风险与不足
  11. 后续行动计划
  12. 参考知识来源
- **验收标准**：
  - [ ] 12 个章节完整
  - [ ] 可直接阅读，不需要额外排版
  - [ ] 同时输出 JSON 和 Markdown 两种格式

### 2.4 AgentEval 测评模块

#### FR-EVAL-001：Case 管理

- **优先级**：P2（Phase 3）
- **描述**：从 JSON 文件加载测评 case
- **Case 结构**：
  ```json
  {
    "case_id": "rag_001",
    "category": "rag_retrieval",
    "prompt": "用户输入...",
    "expected_type": "json",
    "expected_keywords": ["关键词1", "关键词2"],
    "max_length": 1200
  }
  ```
- **10 个类别**，每类 4 个 case，共 40 个 case：
  - `jd_extraction`, `resume_extraction`, `github_project_analysis`
  - `rag_retrieval`, `match_scoring`, `salary_calculation`
  - `resume_advice`, `github_project_advice`, `interview_plan`
  - `safety_honesty`

#### FR-EVAL-002：评分规则

- **优先级**：P2（Phase 3）
- **评分规则**：
  - API 失败：0 分
  - 空回答：0 分
  - JSON 解析失败：-50
  - 超过 max_length：-25
  - 缺少关键词：每个 -20
  - refusal case 未拒绝：0 分
  - RAG case 缺少 rag_sources：-30
  - GitHub case 缺少项目建议：-30
- **通过线**：score ≥ 70

#### FR-EVAL-003：报告生成

- **优先级**：P2（Phase 3）
- **描述**：生成 CSV 和 HTML 两种格式的测评报告
- **CSV 报告**：包含所有 case 的详细得分
- **HTML 报告**：包含：
  - 总通过率
  - 各类别通过率
  - 平均耗时
  - RAG 引用率统计
  - 失败原因统计
  - 每个 case 的详情

### 2.5 API 模块

#### FR-API-001：健康检查

- **方法**：`GET /health`
- **响应**：`{"status": "ok"}`
- **优先级**：P3（Phase 4）

#### FR-API-002：Agent 分析

- **方法**：`POST /agent/analyze`
- **请求体**：完整的 Agent 输入（简历+JD+GitHub项目+可选参数）
- **响应**：完整的 Agent 输出（JSON）
- **优先级**：P3（Phase 4）

#### FR-API-003：RAG 搜索

- **方法**：`POST /rag/search`
- **请求体**：`{"query": "...", "top_k": 5}`
- **响应**：检索结果列表
- **优先级**：P3（Phase 4）

#### FR-API-004：薪资计算

- **方法**：`POST /agent/salary`
- **请求体**：薪资参数
- **响应**：薪资计算结果
- **优先级**：P3（Phase 4）

#### FR-API-005：测评运行

- **方法**：`POST /eval/run`
- **描述**：触发 AgentEval 运行
- **优先级**：P3（Phase 4）

### 2.6 安全与诚信模块

#### FR-SAFETY-001：禁止伪造

- **优先级**：P0（必须始终生效）
- **禁止行为**：
  - 伪造学历/学位
  - 伪造工作经历/实习经历
  - 伪造项目经历
  - 伪造开源贡献（如"给 LangChain 提过 PR"）
  - 伪造论文/出版物/获奖
  - 伪造项目功能/线上部署状态
- **允许行为**：
  - 优化真实经历的措辞
  - 建议构建小型项目填补技能空白
  - 标注缺失技能
  - 将课程项目/个人项目如实包装
  - 提供学习和项目构建计划
- **验收标准**：
  - [ ] safety_honesty 类 AgentEval case 100% 通过

#### FR-SAFETY-002：Mock 数据规范

- **描述**：所有示例数据必须是虚构的
- **禁止**：使用真实人名、电话、邮箱、学校 ID、公司内部信息
- **验收标准**：
  - [ ] 所有 `data/` 目录下的示例文件只包含虚构数据

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 目标 | 测量方式 |
|------|------|----------|
| CLI 端到端耗时（非流式） | < 30s | 示例 case 计时 |
| RAG 检索延迟 | < 500ms | 单次检索计时 |
| API 响应时间（P95） | < 60s | 压力测试 |
| 并发 API 请求 | 支持 5 并发 | 并发测试 |

### 3.2 可维护性

- 模块间低耦合：rag/、tools/、agent/ 三层可独立测试
- 统一异常处理：所有模块使用自定义异常类
- 结构化日志：使用 Python logging 模块，支持 DEBUG/INFO/WARNING/ERROR 级别
- 代码注释：所有公共 API 包含 docstring（Google 风格）

### 3.3 可扩展性

- LLM Client 抽象：支持通过配置切换不同的 LLM 提供商
- RAG 检索可替换：TF-IDF → FAISS/ChromaDB 平滑升级
- 工具可插拔：新增工具只需注册到 ToolRegistry

### 3.4 安全性

- API 输入校验：使用 Pydantic 进行严格的输入验证
- 敏感信息检测：检测并警告简历中的个人隐私信息
- 关闭流式输出时的敏感内容过滤

### 3.5 兼容性

- Python：3.10, 3.11, 3.12
- 操作系统：Windows 10+, macOS 12+, Ubuntu 20.04+
- LLM API：Anthropic API（主），可配置 OpenAI 兼容 API
