### 2.2 架构风格

- **分层架构**：Entry → Agent（编排）→ RAG/Tools/LLM（能力）→ Data（数据）
- **模块化设计**：每层独立模块，单层可测试
- **工具链模式**：确定性计算由 Python 工具完成，推理和生成由 LLM 完成

### 3.2 LLM Client 模块

#### 设计原则

- **抽象接口**：所有 LLM 调用通过统一的 `LLMClient` 抽象接口
- **多提供商支持**：Anthropic（主）/ OpenAI（备）/ Mock（测试）
- **配置驱动**：通过环境变量切换提供商
- **错误处理**：统一的重试机制和降级策略

#### 接口定义

```python
from abc import ABC, abstractmethod
from typing import Optional, Dict, Any

class LLMClient(ABC):
    """LLM 客户端抽象基类"""

    @abstractmethod
    def chat(
        self,
        messages: list[dict],
        system_prompt: Optional[str] = None,
        temperature: float = 0.7,
        max_tokens: int = 4096,
        response_format: Optional[dict] = None,
    ) -> str:
        """发送聊天请求，返回文本响应"""
        ...

    @abstractmethod
    def chat_json(
        self,
        messages: list[dict],
        system_prompt: Optional[str] = None,
        temperature: float = 0.3,
        max_tokens: int = 4096,
    ) -> dict:
        """发送聊天请求，返回解析后的 JSON"""
        ...
```

#### 配置项

| 环境变量 | 说明 | 默认值 |
|----------|------|--------|
| `LLM_PROVIDER` | LLM 提供商 | `anthropic` |
| `ANTHROPIC_API_KEY` | Anthropic API Key | — |
| `ANTHROPIC_MODEL` | Claude 模型 | `claude-sonnet-4-6` |
| `OPENAI_API_KEY` | OpenAI API Key | — |
| `OPENAI_MODEL` | OpenAI 模型 | `gpt-4o` |
| `LLM_MAX_RETRIES` | 最大重试次数 | `3` |
| `LLM_TIMEOUT` | 请求超时（秒） | `120` |
| `LLM_MOCK_MODE` | Mock 模式开关 | `false` |

### 3.3 RAG 模块

#### 架构设计

```
┌──────────────────────────────────────────────────┐
│                   KnowledgeBase                  │
│  ┌────────────┐  ┌──────────┐  ┌─────────────┐  │
│  │DocumentLoader│  │ Chunker  │  │  Retriever  │  │
│  │             │  │          │  │             │  │
│  │ *.md 文件   │→ │ 分块 +    │→ │ TF-IDF      │  │
│  │ metadata    │  │ metadata  │  │ (Phase 1)   │  │
│  │ 提取        │  │ 保留      │  │ FAISS       │  │
│  │             │  │          │  │ (Phase 3+)  │  │
│  └────────────┘  └──────────┘  └─────────────┘  │
└──────────────────────────────────────────────────┘
```

#### 数据流

```
Markdown 文件
  → DocumentLoader.load()
    → List[Document] (content + metadata)
      → Chunker.split()
        → List[Chunk] (每个 300-800 字符, 保留 metadata)
          → Retriever.build_index()
            → TF-IDF 矩阵（Phase 1）/ FAISS 向量索引（Phase 3）
              → Retriever.retrieve(query, top_k, filters)
                → List[RetrievedChunk] (content, score, source)
```

#### 升级路径

| 阶段 | 检索方式 | 优势 | 限制 |
|------|----------|------|------|
| Phase 1 | TF-IDF + 关键词 | 无外部依赖，本地运行 | 语义理解弱 |
| Phase 3 | FAISS + 本地 Embedding | 向量语义搜索 | 需要 embedding 模型 |
| 未来 | ChromaDB + 云端 Embedding | 持久化 + 更高精度 | 需要外部 API |

### 3.4 Tools 模块

#### 工具注册机制

```python
class ToolRegistry:
    """工具注册表，管理所有可用工具"""

    _tools: Dict[str, Callable] = {}

    @classmethod
    def register(cls, name: str, tool_fn: Callable):
        """注册工具"""
        cls._tools[name] = tool_fn

    @classmethod
    def get(cls, name: str) -> Callable:
        """获取工具"""
        return cls._tools[name]

    @classmethod
    def list_tools(cls) -> list[str]:
        """列出所有工具"""
        return list(cls._tools.keys())
```

#### 工具分类

| 分类 | 工具 | 确定性 | LLM 辅助 |
|------|------|--------|----------|
| 解析 | JD Parser, Resume Parser, GitHub Parser | ❌ | ✅ |
| 评分 | Match Scorer, GitHub Scorer | ✅ | ❌ |
| 计算 | Salary Calculator | ✅ | ❌ |
| 匹配 | Keyword Matcher | ✅ | ❌ |
| 生成 | Report Writer | ❌ | ✅ |

#### 关键设计决策

1. **步骤 2-4 可并行**：JD/简历/GitHub 解析互不依赖，可并发执行
2. **步骤 6-8 使用工具计算**：不依赖 LLM，保证确定性和准确性
3. **步骤 9-11 使用 LLM+RAG**：需要生成能力和知识支撑，同时可并行
4. **步骤 12 安全卡点**：在任何输出之前进行安全检查

## 6. 异常处理策略

### 6.1 异常层次

```
JobFunException (base)
├── ConfigError           # 配置错误
├── LLMError              # LLM 调用错误
│   ├── LLMTimeoutError
│   ├── LLMAuthError
│   └── LLMRateLimitError
├── RAGError              # RAG 模块错误
│   ├── KnowledgeBaseNotFoundError
│   └── RetrievalError
├── ToolError             # 工具执行错误
│   ├── ParsingError
│   └── CalculationError
├── ValidationError       # 输入验证错误
└── SafetyViolationError  # 安全策略违反
```

### 6.2 处理原则

1. **LLM 调用失败**：自动重试（最多 3 次），使用指数退避
2. **JSON 解析失败**：尝试正则提取 → 重新调用 LLM（1 次）→ 返回错误
3. **RAG 检索为空**：标记为"无相关知识匹配"，继续流程
4. **工具计算异常**：捕获异常，在报告中标注该部分不可用
5. **安全策略触发**：中断流程，返回拒绝说明

### 7.1 日志级别

| 级别 | 用途 |
|------|------|
| DEBUG | 详细的调试信息：RAG 检索详情、LLM 请求/响应 |

## 9. 技术选型理由

| 技术 | 选择理由 |
|------|----------|
| **Python 3.10+** | LLM 生态最好，开发效率高 |
