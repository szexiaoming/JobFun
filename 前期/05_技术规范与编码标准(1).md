### 1.4 Docstring 规范

```python
def retrieve(
    self,
    query: str,
    top_k: int = 5,
    filters: dict | None = None
) -> list[RetrievedChunk]:
    """从知识库中检索与查询最相关的文档片段。

    使用 TF-IDF 向量相似度计算查询与所有 chunk 的匹配分数，
    返回 Top-K 个最相关的结果。

    Args:
        query: 查询字符串，可以是自然语言问题或关键词。
        top_k: 返回的最大结果数量。默认为 5。
        filters: 可选的过滤条件，支持按 doc_type 过滤。
            示例: {"doc_type": "github_project_rules"}

    Returns:
        按相似度降序排列的 RetrievedChunk 列表。
        如果知识库为空，返回空列表。

    Raises:
        KnowledgeBaseNotBuiltError: 在 build_index() 之前调用了 retrieve()。
        RetrievalError: 检索过程中发生计算错误。

    Example:
        >>> kb = KnowledgeBase("data/knowledge_base")
        >>> kb.build_index()
        >>> results = kb.retrieve("如何优化简历", top_k=3)
        >>> len(results)
        3
    """
```

## 3. 错误处理规范

### 3.1 异常使用

```python
# ✅ 正确：使用自定义异常
from src.exceptions import KnowledgeBaseNotFoundError, RetrievalError

def load_documents(kb_dir: str) -> list[Document]:
    if not Path(kb_dir).exists():
        raise KnowledgeBaseNotFoundError(
            f"Knowledge base directory not found: {kb_dir}",
            detail={"kb_dir": kb_dir}
        )
    try:
        files = list(Path(kb_dir).glob("*.md"))
    except Exception as e:
        raise RetrievalError(
            f"Failed to scan knowledge base directory: {e}",
            detail={"kb_dir": kb_dir, "error": str(e)}
        ) from e
    return [Document.from_file(f) for f in files]

# ❌ 错误：使用裸 Exception
def load_documents(kb_dir):
    files = os.listdir(kb_dir)  # 可能抛出任何异常
    return files
```

### 3.2 LLM 调用重试模式

```python
import time
from src.exceptions import LLMError

MAX_RETRIES = 3
RETRY_BACKOFF = [1, 2, 4]  # 指数退避（秒）

async def call_llm_with_retry(llm_client, messages, **kwargs):
    last_error = None
    for attempt in range(MAX_RETRIES):
        try:
            return await llm_client.chat(messages, **kwargs)
        except LLMRateLimitError as e:
            last_error = e
            if attempt < MAX_RETRIES - 1:
                time.sleep(RETRY_BACKOFF[attempt])
                continue
            raise
        except LLMError:
            raise  # 非限流错误直接抛出
    raise last_error
```

### 3.3 JSON 解析容错

```python
import re
import json

def safe_json_parse(llm_output: str) -> dict:
    """安全解析 LLM 输出的 JSON，带多重 fallback。"""
    # 尝试 1：直接解析
    try:
        return json.loads(llm_output)
    except json.JSONDecodeError:
        pass

    # 尝试 2：提取 ```json 代码块
    match = re.search(r'```json\s*(.*?)\s*```', llm_output, re.DOTALL)
    if match:
        try:
            return json.loads(match.group(1))
        except json.JSONDecodeError:
            pass

    # 尝试 3：提取 { } 包裹的内容
    match = re.search(r'\{.*\}', llm_output, re.DOTALL)
    if match:
        try:
            return json.loads(match.group(0))
        except json.JSONDecodeError:
            pass

    # 所有尝试失败
    raise ParsingError(
        "Failed to parse LLM output as JSON after all fallback attempts",
        detail={"llm_output_preview": llm_output[:200]}
    )
```

### 7.2 敏感信息检测

```python
import re

SENSITIVE_PATTERNS = {
    "phone": r'1[3-9]\d{9}',
    "email": r'[\w\.-]+@[\w\.-]+\.\w+',
    "id_card": r'\d{17}[\dXx]',
    "student_id": r'\d{10,12}',
}

def detect_sensitive_info(text: str) -> list[dict]:
    """检测文本中的敏感个人信息。"""
    findings = []
    for category, pattern in SENSITIVE_PATTERNS.items():
        matches = re.findall(pattern, text)
        for match in matches:
            findings.append({
                "category": category,
                "matched": match,
                "masked": match[:3] + "***" + match[-2:]
            })
    return findings
```

### 7.3 诚实策略执行

```python
# src/agent/career_agent.py

HONESTY_CHECK_PROMPT = """\
检查以下生成的建议是否包含伪造信息。

禁止的内容：
- 伪造学历、工作经历、实习经历
- 伪造项目、开源贡献、论文、获奖
- 伪造项目功能或线上部署状态

如果发现任何伪造建议，返回：
{"safe": false, "violations": ["..."]}

如果没有伪造，返回：
{"safe": true}
"""

async def safety_check(self, generated_output: dict) -> bool:
    """在输出前检查是否违反安全策略。"""
    result = await self.llm.chat_json(
        messages=[{"role": "user", "content": HONESTY_CHECK_PROMPT}],
        temperature=0.0,  # 低温，提高一致性
    )
    if not result.get("safe", False):
        raise SafetyViolationError(
            f"Safety check failed: {result.get('violations', [])}"
        )
    return True
```

## 8. 性能规范

### 8.1 性能目标

| 操作 | 目标 | 备注 |
|------|------|------|
| RAG 索引构建 | < 2s | 150 个 chunks |
| RAG 单个检索 | < 500ms | 本地 TF-IDF |

### 8.2 性能优化策略

1. **并行执行**：JD/Resume/GitHub 解析和简历/项目/面试建议利用 `asyncio` 并行
2. **惰性加载**：RAG 索引在首次检索时构建，而非初始化时
3. **结果缓存**：相同查询的 RAG 检索结果缓存 5 分钟
4. **Prompt 缓存**：利用 Anthropic API 的 prompt caching 减少重复 system prompt 开销
